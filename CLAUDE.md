## Что это за проект

**Минги-Тау** — закрытое мобильное/веб-приложение (сообщество) для карачаевцев
и балкарцев по всему миру. Вход только по приглашению. Подпись бренда:
«Карачаево-Балкарское сообщество». Проект некоммерческий.

Основатель проекта — **Мурат Курджиев**, не программист. Правила работы с ним:

- Строго пошагово, одно действие за раз, без жаргона.
- Окружение: Windows, PowerShell, VS Code, папка проекта `C:\dev\Diaspora`.
- Отправка на GitHub: Source Control → Commit → Sync Changes.
- Всегда давать готовые файлы (не просить писать код руками).
- Одиночные файлы называть по пути с `__` вместо `/`
  (пример: `app__(tabs)__index.tsx`), всегда писать куда положить и как
  переименовать. Больше двух файлов — zip-архив со структурой папок.
- После каждой вехи обновлять CLAUDE.md. После трёх вех в одном чате —
  напомнить открыть новый чат и подготовить стартовый текст.
- Второстепенные пожелания записывать в раздел «Отложенные задачи».

## ПОДТВЕРЖДЕНИЕ ПОЧТЫ (Веха 8) — собственная система, переносимая

Почта подтверждается **своим** 6-значным кодом, а не встроенным механизмом
Supabase. Сделано так специально: при переезде на Яндекс переедет целиком.

- Ящик проекта: `mingi-tau-id@yandex.ru`, отправка по SMTP
  (`smtp.yandex.ru:465`, пароль приложения типа «Почта», в настройках ящика
  включён доступ по IMAP/SMTP).
- Секреты Supabase: `YANDEX_SMTP_USER` (полный адрес), `YANDEX_SMTP_PASS`
  (пароль приложения без пробелов). После смены секретов функцию нужно
  задеплоить заново.
- Таблица `public.email_verification_codes` (email, code, created_at,
  expires_at, attempts, verified). RLS включён — доступ только у функции.
- Edge Function `send-email-code` (действия `send` и `verify`):
  код живёт 10 минут, пауза между отправками 60 сек, максимум 5 попыток
  ввода, старые коды удаляются при новой отправке.
- **ВАЖНО про письмо:** тема и имя отправителя — ТОЛЬКО ЛАТИНИЦА
  (`Mingi-Tau: code 123456`). Кириллица в заголовке даёт крякозябры, а
  ручное кодирование RFC 2047 приводит к двойному кодированию — не делать.
  Русский текст живёт внутри письма (html + content) — там всё в порядке.
- Поток регистрации: шаг 1 контакты → отправка кода → шаг 2 ввод кода
  («Изменить почту» возвращает на шаг 1 с сохранением полей, повторная
  отправка с таймером) → шаг 3 анкета. Инвайт тратится только при финальной
  отправке.
- Решено: **телефон НЕ подтверждаем** (SMS платные; защита обеспечена
  инвайтом и модерацией).

## ДИЗАЙН-СИСТЕМА (утверждена, основополагающая для ВСЕХ экранов)

Стиль: светлый, воздушный, пастельный «iOS / liquid glass». Отсылки к
культуре: логотип-гора и знак **текмет** (круг + ромб + точка).

**Живой фон с боке:** welcome, splash, pending-approval и вкладка «Люди»
до начала поиска (главный экран — визитная карточка сообщества). Как только
показан список людей, фон становится белым, чтобы карточки читались.
Экраны с формами и все прочие рабочие экраны — белые `#FFFFFF`.

**Стекло (Glass) — только точечно:** поля ввода, кнопки, отдельные карточки.
В СПИСКАХ СТЕКЛО НЕ ИСПОЛЬЗОВАТЬ: размытие пересчитывается для каждой
карточки и прокрутка начинает дёргаться. Карточки списков — обычные белые
(`#FFFFFF`, радиус 18, абрис `rgba(93,140,120,0.28)`, толщина 0.75).

**Иконки:** текмет во всю ширину на прозрачном фоне, зелёный `#69B78D`.
Исключения: apple-touch-icon и maskable — на белой подложке; Android —
знак в безопасной зоне. Файлы: `assets/images/`, `public/icons/`.

### Общие файлы

`components/mingi.tsx` — Glass (слои с `pointerEvents="none"`, контент
через zIndex), Blob, useDrift, Tekmet, MingiBackground (уникальный
`idPrefix`). Побочный эффект при импорте: глобально отключает чёрную
браузерную рамку фокуса в вебе.

`components/MingiTabBar.tsx` — СВОЯ панель вкладок. Стандартная панель
react-navigation подмешивала лишние элементы (точки под иконками) и криво
считала высоту; своя даёт полный контроль. Только иконки, без подписей;
активная — закрашенная и тёмно-зелёная `#3F6B5B`, остальные `#A8BDB1`.
Порядок и иконки задаются массивом `TABS` внутри файла.

`components/TopBar.tsx` — верхняя строка: слева аватар → профиль, справа
колокольчик → уведомления (принимает `unreadCount`, `transparent`,
`centerContent`).

`components/AvatarCrop.tsx` — окно кадрирования фото: перетаскивание,
масштаб − / +, круг, обрезка 512×512 JPEG. Экспортирует
`prepareAvatarSource()` — сразу уменьшает фото (≤ 1600 px).

## ИНВАЙТЫ (Веха 15) — логика передачи

- Разделы: **Созданные (не переданные) · Переданные · Пришли**.
- **Любая передача кода наружу помечает инвайт переданным** (поле
  `sent_at`): копирование, «Телеграм», «WhatsApp». Так видно, какой код
  уже кому-то отдан, и его не отправят дважды.
- Кнопки карточки: Копировать · Телеграм · WhatsApp · Удалить.
  Мессенджеры открываются прямой ссылкой с готовым текстом
  (`t.me/share/url`, `wa.me/?text=`) — системное меню «Поделиться»
  НЕ используется: в браузере на компьютере его нет и оно валится ошибкой.
- Кнопка вверху только создаёт инвайт, отправку выбирает человек.
- «Пришли» = люди, зарегистрировавшиеся по кодам. Пусто, пока человек не
  завершил регистрацию ИЛИ пока модератор не одобрил его анкету — инвайт
  помечается использованным только после одобрения.
- Удаление инвайта подтверждается вторым нажатием кнопки.

## ЖИВОЕ ОБНОВЛЕНИЕ (Веха 16) — ВАЖНО ПРИ ПЕРЕЕЗДЕ

`services/liveService.ts` — ЕДИНСТВЕННОЕ место, где используется механизм
трансляции изменений Supabase (Realtime). Экраны знают только функцию
`subscribeToChanges(имя, [таблицы], onChange)`. **При переезде на Яндекс
переписывается только этот файл**; если трансляции не будет — внутри него
возвращается опрос по таймеру, экраны не меняются.

В трансляцию (`alter publication supabase_realtime add table ...`) включены:
`notifications`, `users`, `moderation_messages`, `invite_requests`,
`name_change_requests`, `complaints`.

Живут на живом обновлении: колокольчик и экран уведомлений, экран
ожидания одобрения, экран модерации. Кнопки «Обновить» нигде нет —
экраны обновляются сами, тихо (без мигания загрузки).

⚠️ Побочный эффект: таблица `users` целиком в трансляции. Данные защищены
построчными правилами (RLS), но если появятся чувствительные поля — сузить.

## УВЕДОМЛЕНИЯ: ПОЛНАЯ КАРТА ТРИГГЕРОВ

Все уведомления создаются ТРИГГЕРАМИ В БАЗЕ (не в приложении) — работают
при любом способе действия. Ссылка ведёт точно к месту события:
`/moderation?tab=<очередь>&focus=<id>` — экран сам открывает нужную
вкладку и раскрывает карточку.

Модераторам и основателю:

- новая заявка на вступление (`users` insert, status pending);
- анкета исправлена (`users` update `moderator_has_unread_changes` → true);
- новая жалоба (`complaints` insert);
- заявка на смену имени (`name_change_requests` insert);
- сообщение от участника (`moderation_messages` insert, author_role=user);
  **не дублируется** с «Анкета исправлена»: функция проверяет, не ушло ли
  такое уведомление за последние 30 секунд.

Участнику:

- решение по анкете (одобрено / отклонено / на доработку);
- решение по смене имени;
- его инвайт использован;
- жалоба рассмотрена (без подробностей о мерах);
- новое личное сообщение (создаётся в `messageService`).

**Решения о приватности:** заявителю не сообщается, что именно сделали с
нарушителем; тому, на кого пожаловались, уведомление НЕ приходит вовсе.

**Рубильник «Выходной»** — поле `users.moderation_notifications_enabled`.
Реализован привратником: триггер `skip_muted_moderation` BEFORE INSERT на
`notifications` отменяет запись, если `type = 'moderation'`, а у получателя
рубильник выключен. Поэтому пять функций уведомлений править не пришлось —
и будущие пуши погаснут автоматически. Кнопка в шапке модерации.

## ПРАВИЛА ДОСТУПА И БЛОКИРОВОК (Веха 17)

- Модератор видит скрытый телефон и прочие контакты — **но только пока его
  не заблокировали**. Если участник заблокировал модератора (не зная, что
  тот модератор), модератор становится для него обычным участником:
  скрытые поля не видны, писать нельзя.
- **Основателю доступно всё и всегда**: скрытые контакты, переписка,
  чат — блокировки на него не действуют.
- В чате (`app/chat.tsx`) добавлена проверка блокировки — раньше её НЕ БЫЛО
  вовсе: заблокированные могли переписываться в старом диалоге.
  При блокировке просто исчезает поле ввода, **без пояснений** (решение
  владельца: человек не должен понимать, что его заблокировали).
- Удалять профили может ТОЛЬКО основатель (проверка в интерфейсе и в
  функции). Удаление мягкое: `is_deleted`, плюс `deleted_by` и `deleted_at`.
  Подтверждается вторым нажатием. Вход удалённого перехватывается в
  `app/index.tsx` и `login.tsx` → экран `profile-deleted`.
- Если человека удалили или заблокировали, пока он в приложении, `TopBar`
  ловит это через живое обновление и **сразу уводит** на нужный экран.
