## Что это за проект

**Минги-Тау** — закрытое мобильное/веб-приложение (сообщество) для карачаевцев
и балкарцев по всему миру. Вход только по приглашению. Подпись бренда:
«Карачаево-Балкарское сообщество». Проект некоммерческий.

Основатель проекта — **Мурат Курджиев**, не программист. Правила работы с ним:

- Строго пошагово, одно действие за раз, без жаргона.

- Отправка на GitHub: Source Control → Commit → Sync Changes.
- Всегда давать готовые файлы (не просить писать код руками).

  режет с ошибкой про dollar-quoted string), метки `$$` делать разными.

- **Письмо: тема и имя отправителя ТОЛЬКО ЛАТИНИЦЕЙ** (кириллица в

## ОБРАЩЕНИЯ К АДМИНИСТРАЦИИ (Вехи 23–24)

Раньше `contact-admin` писал сообщение как часть заявки на вступление —
у одобренных/удалённых карточки в очереди нет, обращение терялось.
Теперь:

- Таблица `public.appeals` (user*id, status open/closed, assigned*\_,
  closed\_\_, review_note). RLS: свои читает хозяин, всё — модераторы;
  вставка только своих; правка — модераторы. Включена в realtime.
- Сообщения — в `moderation_messages` с `request_type='appeal'`,
  `request_id` = id обращения.
- `contact-admin` маршрутизирует: анкета в очереди/на доработке — по-старому
  в карточку заявки; удалённый — обращение + текст «модератор свяжется по
  телефону» (уведомлений он не видит!); остальные — обращение + текст про
  колокольчик.
- В модерации ОТДЕЛЬНОЙ ВКЛАДКИ НЕТ (решение владельца): обращения идут
  общим конвейером — свободные в «Новом» (ярлык и фильтр «Обращения»),
  взятые в «В работе», закрытые в «Завершено» (пометка «Закрыто»,
  переписка внутри, кнопки «Изучить» нет — старый экран деталей про них
  не знает). В карточке: автор (нажатие → профиль), переписка, поле
  ответа, «Взять в работу» / «Закрыть». «Закрыть» срабатывает СРАЗУ, без
  модального окна; пояснения модератор пишет через «Ответить».
- «Одна переписка — одна карточка»: новое сообщение человека добавляется
  в его ОТКРЫТОЕ обращение (даже если оно в работе); новая карточка
  создаётся только после закрытия старой.
- **Обращения удалённых видит ТОЛЬКО основатель** (решает о
  восстановлении): фильтр в сервисе (`author.is_deleted`), в счётчике и в
  уведомлениях. У удалённого автора вместо поля ответа — пояснение и
  только «Закрыть».
- Сервис (`moderationService`): getOpenAppeals, getClosedAppeals,
  takeAppeal, closeAppeal, replyToAppeal, getAppealMessages,
  sendAppealMessage (для участника), restoreUser; обращения входят в
  счётчик задач модерации.
- Триггеры в базе: `trg_appeal_message` → `notify_on_appeal_message`
  (участник написал → модераторам, `is_moderation_task=true`, ссылка в

  «Обращение удалённого участника»; модератор ответил → автору);
  `trg_appeal_closed` → `notify_on_appeal_closed` (закрытие → автору,
  с review_note). Старый `notify_moderators_on_user_message` пропускает
  `request_type='appeal'` (иначе был дубль уведомлений).

## ПРАВИЛА ДОСТУПА И БЛОКИРОВОК (Веха 17, дополнено Вехой 35)

**Две разные блокировки:**

1. **Личная** (участник ↔ участник, `userBlockService`): скрывают
   контакты друг друга, писать нельзя. Заблокировавший (А) видит на
   карточке Б серую строчку «Участник заблокирован» — напоминание себе.
   Б и остальные НЕ видят ничего; единственный намёк для Б — в чате
   пропадает поле ввода, БЕЗ пояснений (решение владельца).
2. **Административная** (`is_blocked`, кнопка у админов): человек
   отключён от сообщества — часовой уводит его на `access-restricted`
   (оттуда — обращение к администрации и автовозврат после снятия).
   Правило в базе прячет его из списков и карточек для обычных
   участников. Красный чип «ЗАБЛОКИРОВАН» под аватаром видят ТОЛЬКО
   основатель и модераторы. В меню «⋮» пункт-переключатель:
   «Заблокировать участника» / «Снять блокировку участника»
   (список заблокированных со снятием есть и в Модерации).
   Обращения от заблокированных в модерации: пометка и только
   «Закрыть», без поля ответа (решение владельца, Веха 35).

- Модератор видит скрытые контакты, только пока его не заблокировали.
- **Основателю доступно всё и всегда** — блокировки на него не действуют.
- Удаление/восстановление — только основатель (см. раздел выше). Вход
  удалённого/заблокированного перехватывают `app/index.tsx` и
  `login.tsx`; на живую это делает часовой `AccountGuard` (Веха 35).
